    A library from a BibTeX file¶

    This tutorial follows the R package's "Semantic Librarian for bib files". A .bib file is what reference managers such as Zotero export. When the entries include abstracts, the file is a ready-made corpus about one person's or one topic's literature.

    The example is tests/fixtures/crump.bib, a Zotero export of 39 publications with their abstracts, the same file the R vignette used. The script version is examples/bibliography.py.

    Exporting from Zotero

    Select a collection, choose Export Collection, and pick the BibTeX or BibLaTeX format. Abstracts are included by default.

    Build the library¶

    sl init libraries/bibliography
sl add libraries/bibliography tests/fixtures/crump.bib
sl build libraries/bibliography

    added     39 documents from tests/fixtures/crump.bib (bibtex)
built with beagle: document (39), word (1429), author (47), venue (24), year (13)

    Each entry is a document, named by its citation key. The title, abstract and keywords are the text. Authors, year and venue (the journal or book) are factors, so each gets its own space. The R vignette needed about forty lines of cleaning code for the braces and escapes of BibTeX; that is now done when the file is read.

    Map the whole bibliography¶

    The R vignette ended with a map of all the abstracts. In the web app, search for a broad word and raise "Results" to see many documents at once:

    sl serve libraries/bibliography --open

    Or compute the map in Python. With three groups, the papers fall into recognizable lines of work:

    from semantic_librarian import Library

lib = Library.open("libraries/bibliography")
labels = lib.space("document").labels
projection = lib.project(labels, n_clusters=3)

    Small libraries¶

    Word meanings are learned only from the documents in the library. Thirty-nine abstracts are enough to group papers sensibly, but word neighbours are rough, as the similarities around 0.3 above show. Results sharpen as the library grows. To add more, run sl add with another file and sl build again; a file that has not changed is skipped.
